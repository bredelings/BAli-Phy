# The `--package-path` command:

-P             <paths>                      Directories to search.
--package-path <paths>

BAli-Phy looks in a list of directories to find loadable objects,
haskell modules, model descriptions, and help files.

The default list includes a user package directory, followed by the system
package directory, if they exist.  When `HOME` is set, these are:

   $HOME/.local/share/bali-phy/packages/
   <exe>/../lib/bali-phy/

On Windows, if `HOME` is not set, the user package directory is instead:

   %LOCALAPPDATA%\bali-phy\packages\

Here `<exe>` is the directory containing the `bali-phy` executable.

You can supply additional directories to search by supplying a list of
directories separated by `:` on Unix-like systems or `;` on Windows.
Alternatively, supply this option more than once.  The directories are
searched, in order, before the default list.

Non-existent directories are pruned from the package-path. The
package-path will be displayed if `--verbose` is given.

For a given package directory `<dir>`, bali-phy looks in:

   <dir>            - for loadable objects                 (*.DLL, *.so)
   <dir>/modules    - for haskell modules                  (*.hs)
   <dir>/functions  - for models, functions, distributions (.json)
   <dir>/help       - for help files                       (*.txt)

# Examples:

   bali-phy -P ~/Devel/bali-phy/master/:~/my-packages/ dna.fasta --test -V

On Windows, quote the list so that it works in both PowerShell and cmd:

   bali-phy -P "C:\Users\me\bali-phy;D:\my-packages" dna.fasta --test -V
